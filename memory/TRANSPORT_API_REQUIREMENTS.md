# متطلبات واجهة برمجة التطبيقات (API) — شركة النقل البري
## مرسلة من: معراج نتورك — لتفعيل قسم «التذاكر» داخل تطبيق وموقع معراج
> لن نبدأ بناء تدفق الحجز قبل استلام هذه الوثائق؛ لا نستخدم أي بيانات أو أسعار تخمينية.

### 1) الوصول والبيئات
1. رابط بيئة التجربة (Sandbox) ورابط الإنتاج.
2. طريقة المصادقة (API Key / OAuth2 / Token) وطريقة تجديد التوكن ومدة صلاحيته.
3. بيانات اعتماد تجريبية + إجراء إصدار بيانات الإنتاج ومن يوقّعه.
4. قائمة عناوين IP المطلوب إضافتها للقائمة البيضاء (إن وُجدت).
5. حدود الاستخدام (Rate Limits) وسياسة الحظر المؤقت.
6. صيغة الأخطاء: رمز الخطأ، الرسالة، وهل الخطأ قابل لإعادة المحاولة أم لا.

### 2) البيانات المرجعية
7. المدن والمحطات ونقاط الانطلاق/الوصول (أكواد ثابتة + أسماء عربية/إنجليزية).
8. المسارات المتاحة وأوقات التشغيل وأيام العمل.
9. فئات المقاعد/الخدمة (عادي، VIP…) وسياسة الأمتعة.
10. العملات المدعومة وطريقة عرض السعر ومكان تقريب الكسور.

### 3) البحث والتوفّر
11. `search(from, to, date, passengers)` → قائمة الرحلات مع: رقم الرحلة، وقت المغادرة/الوصول، المدة، المقاعد المتاحة، السعر.
12. `trip(trip_id)` → تفاصيل الرحلة، المقاطع، شروط التذكرة.
13. **إعادة التحقق من السعر (Live/Recheck Price)** قبل التأكيد — ومدة صلاحية السعر.
14. خريطة المقاعد `seat_map` وهل اختيار المقعد إلزامي أم اختياري.

### 4) بيانات المسافر
15. الحقول الإلزامية لكل مسافر (اسم، هوية/جواز، جنسية، جنس، عمر، هاتف…)، وقواعد التحقق وحدود الأطوال.
16. القيود على الأطفال والرُضّع والمرافقين، وأي متطلبات تصاريح.

### 5) الحجز والإصدار
17. `hold/create` (تجنيب مؤقت) ومدة التجنيب، ثم `confirm`، ثم `issue`.
18. **مفتاح التكرار (Idempotency-Key / Request ID)** لمنع تكرار الحجز عند انقطاع الشبكة — وسلوك النظام عند إعادة الإرسال.
19. المعرّفات الراجعة: `booking_id`، `PNR`، `ticket_number` لكل مسافر.
20. مستندات التذكرة: QR / Barcode / PDF (رابط أو Base64) وصلاحية الرابط.
21. `status(booking_id)` للاستعلام عن الحالة في أي وقت.
22. **Webhook** لتحديثات الحالة: تأكيد، إصدار، تأجيل، إلغاء من الشركة، تغيير الرحلة — مع طريقة توقيع/التحقق من الطلب.
23. مرجع خارجي `external_reference` / `client_reference` لربط الحجز برقم حجز معراج.

### 6) الإلغاء والتعديل والاسترداد
24. `refund_quote(booking_id)` → المبلغ القابل للاسترداد + الغرامات قبل التنفيذ.
25. `cancel(booking_id, reason)` و`reschedule` — الشروط والمدد الزمنية.
26. الرسوم: رسوم إصدار، رسوم إلغاء، رسوم تعديل، ومن يتحمّلها.

### 7) التسعير والعمولة والتحاسب
27. تفصيل السعر: **السعر الصافي للوكيل (Net)**، **سعر البيع للجمهور (Selling)**، الضرائب والرسوم منفصلة.
28. **عمولة الوكيل الفعلية**: النسبة/المبلغ، وهل تُخصم مباشرة أم تُحاسب لاحقاً.
29. طريقة التحاسب: حساب ائتماني (Agency Account/Deposit) أم دفع فوري — وكشف حساب الوكيل وواجهة الاستعلام عن الرصيد.
30. دورة الفواتير والتسوية (يومي/أسبوعي/شهري) ومرجع التسوية.

### 8) الجودة والتشغيل
31. أوقات الاستجابة المتوقعة (SLA) وقناة الدعم الفني وساعات العمل.
32. سجل إصدارات الواجهة (API Versioning) وسياسة التغييرات غير المتوافقة.
33. أي متطلبات نظامية/تنظيمية على بيانات المسافرين وحفظها.

**ملاحظة**: عند استلام ما سبق نبني التدفق الحقيقي:
`Search → Trip → Seat → Passenger → Price Check → Booking → Issue → Ticket → Cancel/Refund`
مع الالتزام بأن يكون السعر والعمولة والقرار المالي من الخادم والمزوّد، بلا أي قيم ثابتة في التطبيق.
